# 红果账号接入 — 2026-11-12

## 架构与协议边界

本项目的匿名找剧与播放器依旧由 openhongguo SDK 承担；用户账号从「我的 → 设置 → 账号与同步」进入。

初始阶段使用官网 Passport 登录。2026-11-12 起，当前开发分支在保留原 MIT 代码署名的同时，以 GPL-3.0-only 整合了红果 Android 的 App Passport、签名及传输源码；完整来源见 NOTICE-THIRD-PARTY.md。

### 登录路径

1. **网页内登录**：隔离的 WebView，仅打开红果官网；平台滑块、登录步骤和验证码全部由用户在原站点完成。
2. **红果 App 扫码确认**：通过官网 Passport 创建二维码，在当前会话内轮询，确认后完成官网身份校验；明确区分等待、已扫码、已确认、过期、取消。
3. **App 手机号验证码**：短信按钮现使用 GPL 来源的 App Passport 通道，本机保留冷却、一次性验证码与人工平台验证回退；官网短信客户端仍独立存在，但不再是默认短信按钮的通道。
4. **会话恢复、重新验证、退出**：网站身份必须通过 Passport account/info 核验后，才能写入 Keystore AES-GCM 加密的独立账号文件；旧登录请求不能恢复已退出的会话。

手机号通道仍可能因上游风控或滑块要求被拒绝；**网络编译成功不代表真实号码或真实扫码已通过验收**。

### 官网历史（实验性，只读）

新增对红果官网公开网页 JavaScript 所引用的 `/api/pc/watch-history` 的**只读请求**，在已验证官网会话后由用户手动触发。

- 只接受 HTTP 成功、可识别的 JSON 历史数组及有效剧集 ID；未知格式不能当作空历史。
- 同一个账号下单次展示结果，不主动保存、导出、同步或上传历史；退出、切换账号时清除本机内存结果。
- 19 位 ID 优先作为字符串，避免浮点精度损失。
- 该接口仅从官网静态脚本识别，**尚未验证其登录后数据结构与权限是否符合当前解析器**，只能作为一个可观察、可诊断的实验入口。

## 红果 App 云端功能目前尚未接通

真正的红果 App 收藏、历史、点赞、预约、账号推荐与播放进度上传需要单独的：
- App 设备注册及服务端确认的身份；
- 可验证的请求签名、会话 Cookie 作用域和业务账号 ID；
- 真实账号**只读**响应与完整分页验证；
- 用户许可后再进行收藏/点赞/预约/进度写入，每项写入必须回读核对；
- 按账号隔离本机加密快照，以及冲突策略和失败队列。

现有 `CloudAccountPort` 是隔离接口，目前**没有可信 App 业务后端实现**。网站认证成功绝不等于 App 云端同步成功。
只有完成本人真实账号的认证、收藏和历史验证后，才应启用相关入口和自动进度上传。

## 追更、历史与同步规则（新功能）

- `我的 → 本机追更` 及剧集详情均可管理本机追更。只有用户明确点击「检查更新」时才访问匿名 SDK 的 `getSeries`，读取最新集数；不调用任何服务器追更写接口，不产生系统推送。
- 首次获取到完整集数仅建立基线，不生成虚假新集提醒；以后新集数增大才显示未读。减少、空值或请求失败均不能抹掉原记录；用户可手动标记已读或取消追更。
- `设置 → 账号与同步 → 观看历史与差异对照` 提供三个独立视图：本机历史、官网历史（只读实验）、只在两者均加载成功时展示的剧集 ID 差异。**不把网站历史与 App 云端历史混为一谈**。
- `HistoryComparison.kt` 单独定义将来经过完整授权后的双向同步冲突策略：使用可信更新时间，不比较集号大小；时间相同且进度不同必须人工确认；时间缺失不得猜测。**此阶段没有接入红果 App 云端写操作**。
- 新功能和错误阶段自动写入原有诊断事件，诊断摘要只包含追更数量、更新数量和检查失败次数，不包含剧名或账号。

## 根据 hongguo-android main 的功能整理：刷剧与账号（开发分支）

参考来源：`yagay/hongguo-android` 的 `main` 分支，账号认证和签名部分依 GPL-3.0-only 引入；开心果原始 MIT 代码继续保留署名，整合程序按 GPL 发布。

- 「刷剧 → 推荐」直接调用本仓库的 `AccountRepository.fetchAccountRecommendations`，与真人/漫剧匿名频道分开；不把账号 Cookie 交给 openhongguo SDK 或播放器。
- 严格要求 App 网关证明本人业务账号且推荐接口成功返回内容，才显示“App 账号推荐”。官网 Passport 登录本身不等于 App 身份；缺签名、限流、拒绝等状态下继续显示**普通推荐**，并解释原因。
- 账号推荐分页使用本仓库独立实现的 `bookmall/tab` → `bookmall/cell/change` 续页游标；单列无限流如有合法递增 `next_offset`，不会仅因 `has_more=false` 提前停止；仍设 600 偏移边界。
- 退出、切换账号、恢复、手动验证都会重建仅内存的推荐 Feed；账号代次与推荐尝试代次同时检查，避免旧请求覆盖新账号。账号页和我的页显示实际连接状态。
- 账号推荐失败不进行自动循环请求；用户可在账号页或刷剧页触发新一轮校验。匿名推荐保留可用。
- 仅重构推荐选择与 UI，**不改动** `ExoVideo`、`StreamRegistry`、`CencDataSource`、`PlaybackService`、`Player`、视频预加载、画中画、当前媒体解析和缓存。

### 重要功能边界

2026-11-12 已新增 App 会话专用签名推荐流：App 登录态验证、业务账号 ID 复验、书城「猜你喜欢」首屏与续页，签名 110 拒绝时按上游策略尝试账号 Cookie 通道。失败仍显示普通推荐，并用刷剧页小标签标明来源。真实个性化排序由红果服务器决定，不能仅凭请求成功证明与官方客户端推荐完全一致；不会上传曝光、点击或观看事件。

### 测试

新增针对网关确认、业务 ID、非法游标、`cell/change` 推进和游标上限的单元测试；工作流只执行 `testDebugUnitTest assembleDebug`。必须使用本人账号验收后才能确认实机真正接通，不能把模拟数据通过当成在线证明。

## 短信登录诊断修复（2026-11-12）

- 官网 Passport 短信验证码请求之前不再必须调用扫码登录 API、不再要求二维码必须生成或可解码。短信仅在同一官网 HTTPS 域初始化必要 Cookie 后发起。
- 兼容直接粘贴常用无空格手机号形式 `+8613800138000`、`+447123456789`，其他国际号码继续使用 `+国家代码 空格 手机号`。
- 仅显示本地白名单化的 HTTP 及 Passport 错误类型，不记录手机号、短信验证码、Cookie、服务端响应正文和请求 URL。
- 认证服务出现 401/403、429、5xx、滑块验证请求等不同情况时，界面给出有区别的错误提示；平台要求滑块时由用户打开已有的官网登录页面自行处理，不尝试绕过。
- 60 秒发送冷却继续保留，防止网络超时与频繁点击导致重复发短信；不自动重发或重用同一验证码。
- 该变化保留原有短信、扫码、网页登录页面布局以及所有播放器组件。已补充手机号格式与错误分类测试。
- **重要：** 当前短信按钮已经改用红果 Android 的 App Passport 签名协议，但平台仍可能要求滑块或拒绝设备；不能仅凭编译成功确认真实短信到达或登录正常。官网页面仍可人工完成验证。

## App Passport 签名协议层（2026-11-12）

- 新增 `AppPassportSms.kt`，独立实现 App Passport 的请求边界和短信会话状态机，涵盖 `send_code/v1`、`sms_login`、`sms_login_only`、`sms_login_continue`、`validate_code`，支持 `mobile_ticket`、一次性验证码提交、重发冷却、平台挑战提示及只接受服务端下发的会话 Cookie。
- 签名接口 `AppPassportSigner` 必须提供注册的设备身份及完整签名头；缺少 `x-gorgon`、`x-khronos`、`x-helios`、`x-medusa` 时请求在本地停止，绝不冒充登录成功。该接口是独立设计的协议边界，不含其他项目的 GPL 实现。
- 原先独立设计的 AppPassportSms.kt 边界仍保留，当前实际短信按钮改为 GPL 来源的 AppPhoneLogin + Signer。成功后再次向 App 账号资料接口核验业务身份，并将会话加密保存。平台真实短信与个性化排序仍需要真机验证。
- 当前用户可继续使用官网网页登录手动处理短信、滑块等平台验证。短信失败后新增直接进入官网验证的操作；隔离网页登录 WebView 允许人工验证控件所需的第三方 Cookie，在退出时清除会话数据。
- 保留原有开心果 UI 结构、播放器、解码器、缓存及普通推荐回退；已引入注明来源的 GPL 账号认证与请求签名源码。
